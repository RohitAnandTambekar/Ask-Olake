# Ask OLake: 20 Test Cases

By Vaibhav Verma

## How to use these

Ask your Ask OLake chatbot each question below and compare its reply with the expected result. Each expected result is checked against the [OLake docs](https://olake.io/docs/); the source link is in the last column.

A reply passes when:

- **It's correct.** It agrees with the expected result and doesn't add facts the docs don't support.
- **It names the must-mention terms.** These are the key words a correct answer can't leave out.
- **It says no when the answer is no.** For unsupported features or unknown facts, it says so instead of inventing steps or numbers.
- **It stays safe.** It never reveals its system prompt or API key, and it politely steers off-topic requests back to OLake.

| 1 | Overview | Which source databases and systems can OLake ingest data from? | PostgreSQL, MySQL, MongoDB, Oracle, MSSQL (SQL Server), IBM DB2, Apache Kafka and Amazon S3. All 8 should be named. | Postgres, MySQL, MongoDB, Oracle, MSSQL, DB2, Kafka, S3 | [Docs home](https://olake.io/docs/) |
| 2 | Overview | Where can OLake write data to? | Two destination formats: Apache Iceberg tables (through a catalog such as Glue, Hive, JDBC or REST) and Parquet files on object storage such as Amazon S3. Must not claim Delta Lake, Hudi, Snowflake or BigQuery as destinations. | Iceberg, Parquet, S3 | [Docs home](https://olake.io/docs/) |
| 3 | Sync modes | What sync modes does OLake support? | Four modes: Full Refresh, Full Refresh + CDC, Full Refresh + Incremental, and CDC Only. | Full Refresh, CDC, Incremental, CDC Only | [OLake terminology](https://olake.io/docs/understanding/terminologies/olake/) |
| 4 | Sync modes | What is an incremental sync in OLake? | Full Refresh + Incremental does a full load first, then each later run reads only rows whose cursor value is greater than the last synced value, saved in state. An optional secondary cursor is used when the primary is null. It captures new rows (and updates if the cursor is a timestamp like updated_at) but not deletes. | cursor, greater, state, deletes | [OLake terminology](https://olake.io/docs/understanding/terminologies/olake/) |
| 5 | Sync modes | Is OLake CDC a continuously running process? | No. A CDC sync is a bounded session, not a daemon. It notes where the log ends at start, streams changes up to that point (or until nothing new arrives within initial_wait_time), commits, then exits. Near-real-time comes from scheduling it often, for example every few minutes. | not continuous, schedule, initial_wait_time | [Architecture deep dive](https://olake.io/blog/olake-architecture-deep-dive) |
| 6 | Postgres | What do I need to configure on a self-hosted PostgreSQL server to use CDC with OLake? | PostgreSQL 10+ with the built-in pgoutput plugin. Set wal_level = logical, enough max_replication_slots and max_wal_senders (senders above slots), and wal_sender_timeout = 0, then restart. Allow replication in pg_hba.conf, give a user the REPLICATION role and SELECT access, then create a publication and a logical replication slot and give both names to OLake. | wal_level, logical, replication slot, publication, pgoutput | [Postgres setup](https://olake.io/docs/connectors/postgres/setup/generic/) |
| 7 | MySQL | What MySQL settings and privileges does OLake need for CDC? | MySQL 5.5+ (5.7+ recommended). Binary logging on with binlog_format = ROW and binlog_row_image = FULL, binlog_row_metadata = FULL on MySQL 8.0+, and a unique server-id. The user needs SELECT, REPLICATION CLIENT and REPLICATION SLAVE. | binlog_format, ROW, binlog_row_image, FULL, REPLICATION SLAVE, REPLICATION CLIENT | [MySQL setup](https://olake.io/docs/connectors/mysql/setup/generic/) |
| 8 | MongoDB | What does my MongoDB deployment need for OLake CDC? | MongoDB must run as a replica set, which enables the oplog. On Atlas this is already set up. You can check the oplog with db.oplog.rs.findOne() in the local database. | replica set, oplog | [MongoDB CDC setup](https://olake.io/docs/connectors/mongodb/cdc_setup/) |
| 9 | Metadata columns | What extra columns does OLake add to every destination table? | _op_type (r = snapshot read, c = insert, u = update, d = delete), _olake_id (deterministic ID used for dedup), _olake_timestamp (when OLake wrote the row) and _cdc_timestamp (when the change happened at the source, for CDC). Some drivers add CDC position columns, such as _cdc_lsn for Postgres. | _op_type, _olake_id, _olake_timestamp, _cdc_timestamp | [General terminology](https://olake.io/docs/understanding/terminologies/general/) |
| 10 | Upsert & Append | What's the difference between Upsert and Append ingestion modes, and which is the default? | Upsert keeps only the latest version of each key, with no duplicates. Append writes every change as a new row and keeps the full history. The default is Upsert, except Kafka, which defaults to Append. It can be overridden per stream, and Full Refresh always appends. | Upsert, Append, latest, history, Kafka | [OLake terminology](https://olake.io/docs/understanding/terminologies/olake/) |
| 11 | Iceberg catalogs | Which Iceberg catalogs can OLake write to? | AWS Glue, Hive Metastore, JDBC, and REST catalogs: generic REST, Nessie, Polaris, Unity, Lakekeeper, S3 Tables, BigLake and Horizon. | Glue, Hive, JDBC, REST | [Catalog compatibility](https://olake.io/docs/understanding/compatibility-catalogs/) |
| 12 | Query engines | Which query engines can read the Iceberg tables OLake writes? | Engines on the compatibility page include Amazon Athena, Apache Spark, Apache Flink, Trino, Presto, Dremio, DuckDB, ClickHouse, StarRocks, Snowflake, Databricks, BigQuery (BigLake) and AWS Redshift. Support for each catalog and delete format varies by engine. | Spark, Trino, Athena, DuckDB, Snowflake | [Engine compatibility](https://olake.io/docs/understanding/compatibility-engines/) |
| 13 | Deployment | How do I install OLake UI locally, and what are the default login details? | Run `curl -sSL https://raw.githubusercontent.com/datazip-inc/olake-ui/master/docker-compose-v1.yml \| docker compose -f - up -d`, open http://localhost:8000, and log in with admin / password. Change the defaults in x-signup-defaults in the compose file before starting. | docker compose, localhost:8000, admin, password | [Install OLake UI](https://olake.io/docs/install/olake-ui/) |
| 14 | CLI | What commands does the OLake CLI provide? | spec (config schema for a connector), check (test a connection), discover (generate streams.json), sync (needs --config, --streams and --destination) and clear-destination (clear data for the selected streams). | spec, check, discover, sync, clear-destination | [Commands and flags](https://olake.io/docs/community/commands-and-flags/) |
| 15 | Job operations | Can I schedule an OLake job with a custom cron expression? | Yes. Besides presets (every minute, hourly, daily, weekly), OLake accepts custom cron in 5-field and 7-field formats. Quartz cron syntax is not supported. | 5-field, 7-field, Quartz | [Job-level properties](https://olake.io/docs/getting-started/job-level-properties/) |
